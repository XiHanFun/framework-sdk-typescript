# TypeScript SDK 测试审查

对每个测试给出「保留、改写、合并或删除」结论，并指出它保护的公开不变量。

- 保留：缺陷复发时会失败，覆盖公开入口的行为、错误码与消息键、取消与截止时间、边界与容量、平台差异或规范向量。
- 改写：只断言内部函数被调用、依赖私有状态或执行顺序、靠长时间真实等待、没有失败路径，或手抄了向量里本该读取的期望值。
- 合并：与相邻用例输入和断言等价，不能提供额外定位。
- 删除：不可能失败、只验证常量或 Node 本身，或已被更清晰的同层测试完整覆盖。

## SDK 专项

- 向量回放要直接读 `spec/conformance/vectors/` 并逐条核对，回放的文件登记在 `test/conformance-vectors.test.ts` 的 `replayed`；不允许挑部分用例。
- 测试经 `xihan-framework/<模块>` 自引用公开入口；直接导入 `src/` 文件的只限回放内部规则的向量（如插件的 `conversion.ts`、`deadline.ts`、`errors.ts`），其余改走公开入口。
- 与时间有关的用例要确定地造出先后（替换 `Date.now`、受控的信号），不靠 sleep；截止与取消的归因要覆盖信号先到、时钟先到两种情形。
- 插件测试区分本进程里的运行时测试（`test/plugin.test.ts`）与黑盒运行器（`test/plugin-conformance.test.ts`）；缺 Go 不能静默跳过，只有 `XIHAN_CONFORMANCE_REQUIRED=0` 才跳过。
- 平台相关的用例（命名管道、Unix 域套接字、启动脚本）要在 Windows 与 Linux 上都有意义，不能只在一个平台上断言为真。
- 测试名用中文，断言消息用英文。

输出按风险排序并附文件和行号。除非用户要求运行，否则只做静态审查；不得通过删除测试或放宽门禁解决实现缺陷。
